# Derived data and the map images

The schema of every data file the viewer is built from, and the map images and marker icons.

## Derived data files

The pipeline turns the game data into the files in `data/`; each section names its script (`npm run data:<name>`, in
the order of `scripts/README.md`). The page embeds `progress.json`, `walk.json`, `level-cells.json`, a cut-down
`schema.json` and `wikitactics.txt`. Scripts and tests also read `world.json` and `rooms.json`. Rebuild the last three
steps with:

```
npm run data:progress
npm run data:walk
npm run data:cells
```

`wikitactics.txt` is not derived: a copy of [joric/ootss data/wt.txt](https://github.com/joric/ootss/blob/main/data/wt.txt),
rows `level,area,anchor`; a level's panel links to `https://sinkingstar.wikitactics.com/areas/<area>/#<anchor>`.

Positions are world units; a cell is (i, j) = ((x − corner.x) mod W, (y − corner.y) mod H) with the overworld grid
corner (−24, −2) and W × H = 190 × 156. The world, fog and map scripts fill a field a blob leaves out with its type
default: the first value stored for that field in any level of the package. A row's trailing `(, exists)` column is
described under [data/world.json](#dataworldjson).

### data/schema.json

Written by the schema exporter ([Reading the schema out of the binary](gamedata.md#reading-the-schema-out-of-the-binary)).
`{base: {name: "Undoable_Entity_Data", fields}, types: {<type>: {version, size, fields}}, enums: {<key>: {flags, values}}}`;
`SchemaField` in `src/types.ts` gives a field's keys.

- A type the exporter could not find is `{missing: true}`. The page's copy (`schemaForPage()` in `vite.config.ts`)
  keeps only the types it decodes, a fixed list of enums including `Achievement`, and the keys `n`, `v`, `k`, `sz`,
  `t` and `e` of a field.
- A field: `n` name (flattened, `position.x`), `v` [first, last] version (−1 = none), `k` kind: `p` plain data (raw
  `sz` bytes), `s` string, `r` resource pointer (by name), `a` dynamic array (`e` the element), `x` anything else.
  `notes` are `NoUndo`, `NoEditorUndo`, `NoEditorSave`.
- Enum keys: the enum's name when it is unique, else the first field that uses it (`Settings.special_level`,
  `Rock.properties`), else `<name>#2`, `#3`. `values` = [[name, value]]. `flags` = an `enum_flags` type.
- The exported enums are the ones fields use, plus a fixed list: `Level_State_Flags`, `Level_State_Misc_Flags`,
  `Move_Type`, `Direction`, `Action_Type`, `Character_Index`, `Character_Rank`, `Status_Flags`, `Entity_Flags`,
  `Transition_Glyph_Flags`, `Tower_Flags`, `End1_Flags`, `Skill_Flags`, `Inventory_Flags`, `One_Time_Bark_Flags`,
  `Achievement`, `Language`, `Promesst_Power`. `Action_Icon` and the undo record `Flags` are not exported.

### data/levels.json and data/level_entities/

Written by `build-levels.ts`. `levels.json` = `{level_sets: {<set>: [level names]}, levels: [...]}`, one row per level in
the package: `name`, `level_sets`, `entity_count`, `namespaces`, `type_counts`, `settings` (the `Settings` fields the
scripts read, type defaults filled in) and `entities` (`{<type>: [{id, pid, fields}]}` for the progression types:
`Level_Entry`, `Area_Pin`, `Teleporter`, `Freezer`, `Tower`, `Sign`, `Gem_Slot`, `Treasure_Display`, `Marker`, ...).

Entity `fields` hold only what the blob stores (a missing field is the type default). Base fields are prefixed `base.`
and only position, `orientation.z/w`, `entity_flags`, `entity_name`, `group_id` and `mesh` are kept. Floats are rounded
to 4 places. Enums are value names; a flags enum is a list of names, plus an int for unnamed bits. Reference fields
(`*_id`, `target_id`, `also_discover`, `map_label_marker_id`, ...) are `["#ns-serial", pid]`, or 0 for none.

`level_entities/<level>.json` = `{level, columns: ["pid", "type", "x", "y", "z", "mesh"], types: [type names], meshes:
[mesh names], ents: [[pid, type index, x, y, z, mesh index or −1]]}` for every entity of the level.

### data/level_areas.json

Written by `build-areas.ts`: the current-area rule applied at each overworld Level_Entry ([Areas](state.md#areas),
[Level areas (viewer)](viewer.md#level-areas-viewer)). `{rule, areas, levels, unassigned}`.

- `areas`: per `local_area_name`, the pin, `display_name` (en), `local_area_image`, the label marker and
  `local_area_boxes: [{p, q, s, e, f, w}]`: `p` position, `q` orientation quaternion (x, y, z, w), `s` scale, `e`
  `props.box_extents`, `f` `float_parameter` (priority, lower wins), `w` the wrap widths used for x and y (the grid
  size, or the fast-travel extents for boxes at map-room height).
- `levels`: per level name. Inside a box: `exact: true`, the `area_pin`, `local_area_name`, `candidates` (how many boxes
  hold it) and, for an entry in boxes of more than one area, `overlap`: [[local_area_name, float_parameter]] in record
  order. Outside every box: `exact: false`, the `nearest_*` area and `margin` (distance outside the nearest box, the
  largest per-axis value).
- `unassigned`: the levels outside every box.

### data/fog.json

Written by `build-fog.ts`.

- `grid` {corner (−24, −2), screen (19, 13), count (10, 12), wrapping}: region = sx + 10 × sy,
  sx = ⌊(x − corner.x) / 19⌋, sy = ⌊(y − corner.y) / 13⌋, wrapped; −1 outside.
- `layers`: the ground layer table, [{index, name, zmin, zmax}] (ONGROUND, UNDERGROUND, SKYGROUND,
  FAST_TRAVEL_UNDERGROUND, FAST_TRAVEL_ONGROUND, FAST_TRAVEL_SKYGROUND; null = unbounded).
- `states`: {0 FILLED, 1 PARTIAL, 2 CLEARED}.
- `primary`: one Fog_Of_War per layer, with z_overrides [[region, zmin, zmax, Fog_Of_War_Z id]]. zmin / zmax = z −
  `descent` / z + `ascent` (defaults 4.5 / 6.5). The first Fog_Of_War_Z per region wins.
- `boxes`: regions = 0 with `clear_as_part_of_room`, else 1; `only_overhang`.
- `clears`: `dir` = `clear_neighboring_screen`, `to` the neighbour region (−1 for none), `radius`.
- `level_entries`: [level_name, layer, region] for the overworld Level_Entries that are not broken or disfavored.
- `area_pins`: [id, local_area_name, layer, region].
- `start`: {hero, regions: {Fog_Of_War pid: [region]}, pins: [Area_Pin pid]}: a fresh campaign whose hero walked
  everywhere reachable at the start, taken as the fog before a save is loaded. It is a fixed value in `build-fog.ts`
  ([Fog of war](state.md#fog-of-war)).

### data/map.json

Written by `build-map.ts`. `{corner, size, layers, oceans}`: the frame of the overhead map, which
[The map images](#the-map-images) fill.

- `corner` is the world position of square (0, 0)'s centre. Square (i, j) covers x in [corner.x + i − 0.5, +1) and
  y in [corner.y + j − 0.5, +1).
- `layers`: [{key, name, z: [z0, z1]}] in the order underworld, ground, sky. A layer holds the z in [z0, z1), from the
  ground layer table: the Settings' underground and skyground barriers and the fast-travel rooms above the sky. The
  underworld has no lower barrier.
- `oceans`: every drawn Ocean_Map that is not PLAYER_BLOCKING_ONLY, with `layer` an index into `layers`. Square k is
  world square (x0 + k % sx, y0 + ⌊k / sx⌋), the drawn surface is at `zw` (z − `sink`), and `water` = base64 of the
  initial bit-0 mask, holes applied (bit k % 8 of byte k >> 3). Only an unrotated map fits this row.

### data/world.json

`{world, teleporters, treasure_displays, gold_rooms}`: the overworld as walkable cells, for the walk model
([The walk model (viewer)](viewer.md#the-walk-model-viewer)). Only scripts and tests read it, through `src/world-data.ts`;
the page does not embed it, and `progress.json` copies the few keys the page reads (`world.grid`, `world.area_pins`,
`world.movables`, a subset of each pad, `treasure_displays`, `gold_rooms`). `l` and `zlayer` values are ground-layer
table indices: 0 ground, 1 underworld, 2 sky, 3-5 the fast-travel map rooms (underworld, ground, sky).

**`exists` column.** A row whose entity can be absent ends in `exists`, its state when the level loads. On load every
existence Group (`is_existence_group`) takes its `exists_by_default`; its stored `exists` is ignored. Its direct members
(other than `EXISTS_FOR_COSMETIC_TRANSITION_PURPOSES_ONLY` ones) get IN_EXISTENCE_GROUP and a CURRENTLY_EXISTS that
follows it, whatever flags they store, and the change passes into existence subgroups. So `exists` is:

- for a direct member of an existence Group: that Group's `exists_by_default`;
- for another entity flagged IN_EXISTENCE_GROUP: its stored CURRENTLY_EXISTS;
- 0 for an entity the cell lookup skips: `EXISTS_FOR_COSMETIC_TRANSITION_PURPOSES_ONLY`, `NOT_SNAPPED_TO_GRID` or
  `PLAYABLE_IN_PRELUDE`.

Rows without the column always exist. The save overrides it: member `entity_flags` CHANGEs, a Group's saved `exists`
(applied to its members and subgroups when it differs from the default) and CREATION_OR_DESTRUCTION records.

The row shapes are the types in `src/types.ts` (`World`, `Teleporter`); the table gives what each key means. A row's
`exists` is the column above, and `i`, `j` are cells.

`map.json` as `map`, and fog. Level roles (Required / Optional, the Freezers each level sits behind) are in

### data/walk.json

Written by `build-walk.ts` (`npm run data:walk`): what the walk model ([The walk model (viewer)](viewer.md#the-walk-model-viewer))
works out from the level data alone, so the page doesn't redo it on every load. It runs the room search
(`searchRooms()`), then the page's own `staticRoles()` and `floorHeights()` with the room answers in use, over
`progress.json`. `WalkFile` in `src/types.ts` gives the shape.

- `inputs`: the SHA-256 (hex) of `progress.json` (without the level table's `needs` and `drop`), `world.json` and the room search's sources (`src/walk/room-search.ts`
  and every `.ts` file it imports). `tests/walk-data.test.ts` fails when they no longer match, or (with `WALK_FULL=1`)
  when the walk on the current code gives other roles, floors or room answers.
- `roles.need`: one digit per level (`progress.json` `levels` order) and per Freezer (`freezers` order): 2 Required,
  1 Required as one of several, 0 Optional ([Level roles (viewer)](viewer.md#level-roles-viewer)).
- `roles.bg`: per Freezer and per Sign, the indices into `freezers` of the Freezers it sits behind, ascending; null for
  a Sign the build walk never reaches.
- `floors`: per map layer key, zlib + base64 of one byte per map column (W × H, row-major, row 0 = north, as
  `map.json`): the highest z where the walk stands the hero there, plus 128; 0 where it stands him nowhere. The flood:
  gates as stored, no Freezer closed, every teleporter enabled and discovered, seeded at every Level_Entry, pad and
  Area_Pin.

### data/level-cells.json

Written by `build-level-cells.ts` (`npm run data:cells`) from the floors of `walk.json`: for each map layer, the level
whose door each standable cell is nearest to by walking, which the Reachable overlay
([The page (viewer)](viewer.md#the-page-viewer)) shades by. Per map layer key it holds zlib + base64 of one
little-endian u16 per map column (as `floors`): the index into `progress.json` `levels` of the nearest level, 0xFFFF
where no door reaches the column. The search runs from every level's door at once, one step to a side at a time, over
the cells that have a floor, wrapping at the map's edges. A step goes onto a cell that stands no higher than the one it
leaves; a cell two doors reach at the same distance goes to the lower level index.

### data/rooms.json

Written by `build-walk.ts` beside `walk.json`; scripts and tests load it, the page does not. The exhaustive push search
of the screen rooms ([Room answers](viewer.md#room-answers)) on the level data. `RoomsFile` in `src/types.ts` gives the
counters; `data` is zlib + base64 of JSON, a list of rooms `[cells, attackers, entries, opens]` as `packRooms()` in
`src/walk/room-answers.ts` packs them.

## The map images

`src/assets/map-<layer>.avif` holds one image per map layer (`underworld`, `ground`, `sky`), each a top-down render of
that layer of the overworld with the fog cleared, the hero hidden and the time frozen.

- An image is 32 pixels per square, W × H squares. Pixel row 0 is the north edge.
- Square (i, j) of the map grid ([data/map.json](#datamapjson)) covers pixels x in [32 i, 32 i + 32) and rows
  [32 (155 − j), 32 (155 − j) + 32). World square (x, y) has its centre at pixel ((x + 24.5) × 32, (153.5 − y) × 32).
- The pixels are opaque RGB. Pits are black.
- The images show everything, fogged parts included; the viewer covers what the save has not uncovered
  ([Fog of war](state.md#fog-of-war)).
- `src/map/thumbs/<layer>.avif` is the same layer at one pixel per square (each pixel the average colour
  of its square, row 0 north). The page embeds the thumbnails and draws a layer's thumbnail pixelated until its full
  image, published in the page's `assets/` folder, has loaded and decoded.

## The marker icons

`src/assets/icons/<name>.avif` holds one 128 × 128 image per marker kind and state, rendered from the game's own
3D models by `scripts/build-icons.ts` (`npm run icons`). The pixels are RGBA on a transparent background: the object
fills the frame (5 pixels of margin), with a thin dark outline and a soft drop shadow so it reads on any terrain. The
whole set is small.

The texture icons are mip 0 scaled down to 128 px and fitted into the square, with no outline or shadow.

- The view is orthographic: the camera sits 25° east of south and 42° above the ground, so a model's front faces
  south, as on the map. The Level_Entry and Teleporter pads are seen straight from above, north up. The sign and the
  gate face +x, so they are seen from the east, 24° above.
- The icon uses the fields of the first placed entity of that type with that model (for the Teleporters, the first
  gold-room endpoint or the first other one).
- The Teleporters' glowing parts take the hue of `color_discovered`, dimmer for a small intensity (its fourth number)
  or a dark colour. The undiscovered pads have no icons: the map dims them.
- Each Level_Entry has its own glow colour, `color_active`. The icons group them into five by hue, `glow` in
  `progress.json` `levels` (green, orange, yellow, blue, purple). The 16-point pads of the tower levels have their own icons, `tower` in `levels`.
- The level pads use the viewer's own colours: locked is dark grey stone (#4a5058) with no glow; available is the group's glow (green #4fe06c, orange
  #ff8a1e, yellow #ffd21a, blue #2ab4ff, purple #b048ff) on mid stone (#8c8a80), also for a level entered but not
  solved; solved is a dim gold stone (#8a7440) with no glow, for every group.
- Shading is a Lambert shade from the vertex normals: a key light from the top left, a fill from the right and a rim
  behind. Normal maps, reflections and shadows are not drawn.
- `favicon-32.png` and `favicon-64.png` are the `Entry_Solved_A` model in bright gold (#e6b83a glow on #b8902c stone)
  seen from straight above, cropped to its star, at 32 and 64 pixels, as PNG.
